# novel-analysis-imitate · 中文中长篇「深度分析 + 跨书仿写/重组」引擎 — 分析与设计

> 兄弟项目,位于 `visible-AI-novel-writer/novel-analysis-imitate/`。现有 `backend/` 是**单书续写**工具;
> 本项目专精**拆解技法/文笔/故事架构/世界观/人物关系/剧情铺陈/节奏**,并在此之上做**跨书仿写与重组**。
> 形态:独立 FastAPI + Next.js;复用方式:把现有 `backend` 当**可 import 的包**(现有项目尽量零改)。

---

## 一、要解决的 4 类目标(用例)

1. **UC1 · 融合世界观+文风写自创剧情**:一组同题材完本书(如 诡秘之主/余烬之铳/诡秘地海/黎明医生/深海余烬 —— 克苏鲁+维多利亚+蒸汽朋克+悬疑),融合它们的**世界观骨架**与**文笔声音**,用来写**我自己的剧情**。
2. **UC2 · 文风迁移**:用 A 书的文笔写我的故事;或用 A 的文笔**给 B 的故事换皮重述**(A 文风 × B 剧情)。
3. **UC3 · 剧情/关系重组移植**:把 A/B/C(玄幻)的**剧情精华 + 人物关系**取精去糟、杂糅成一版,再**移植到克苏鲁世界观**、用其文风写出来。
4. **UC4 · 技法学习与应用**:学江南式**宏大世界观铺垫** + **节奏/结构**技法 —— 何时切 POV、何时拉回主角、何时铺垫/小高潮/大高潮/热血/悬疑惊悚/煽情、金手指如何递进、人物关系如何演变(情人/敌人/朋友/反目/背叛/忠贞/萍水相逢/相忘于江湖……),把这些"技法 DNA"应用到生成。

## 二、复用现有续写项目的哪些模块

**直接 import、当库用(现有项目不改)**

| 现有模块 | 复用点 |
|---|---|
| `app/llm/client.py` | LLM 总入口:多 provider、429 自适应长退避、`response_format`(json_object/json_schema,火山仅 doubao-seed-2.0-pro/lite 支持)、json_repair 兜底 |
| `app/settings/store.py` + `app/config.py` | 模型 lane(FAST/STRONG)、per-agent override、provider 凭据。**共享同一份 `data/settings.json`** |
| `app/ingest/split.py` | 编码探测 + 章节正则切分 + `chapter_fts`(BM25) |
| `app/ingest/extract.py` + `app/memory/{models,schema_init}.py` | 6 抽取 agent(实体/伏笔/状态/剧情/世界/谜团)+ per-book novel.db schema |
| `app/style/pipeline.py` | StyleProfile(声音/POV/叙事结构/套路/词汇/语域/scene_exemplars/median 字数) |
| `app/craft/pipeline.py` | 26 类笔法片段库 + 风格卡 + 写作 few-shot 注入 |
| `app/graph/` | 实体去重 / 关系抽取 / importance 重算 |
| `app/arc/`、`app/outline/`、`app/draft/` | 生成内核:全弧预测、逐章大纲、writer+3审+editor;**Phase 2+ 才用** |
| `app/books/library.py`、`app/db.py` | 多书 slug/路径、active book 机制 |

**跨书核心约束(枢纽)**:现有 `app/db.py` 的 `session_scope()` 走「**单 active book 全局单例**」(读 `data/active_book`)。所有 pipeline 隐式操作"当前那一本"。因此:
- **MVP 采用「串行切 active」**:`books.library.set_active(slug)` → 调现有 pipeline → 读回结果 → 写进本项目的聚合层。现有 backend **一行不改**。代价:不能并发(切换有 engine cache 失效副作用)。
- **后期(Phase 5,可选)** 把全局单例重构成 `with book_scope(slug):`(contextvar),去掉串行限制、支持并发分析。

**生成内核的复用方式(Phase 2+)**:把"融合产物"(自定世界观/人物/伏笔 + 融合 StyleProfile + 笔法卡)**写进一个 compose 虚拟书的 novel.db(同 schema)**,`set_active(虚拟书)` 后直接调 `draft.write_chapter` —— writer 会自动注入 `continuation_style_guide()`(文风)+ `_scene_exemplar_block()`(风格范文 + 26 类笔法 few-shot)+ `_gather_context()`(世界/人物/伏笔/谜团),**整条"模仿写作 + 三审一编辑 ReAct"白嫖,不重写**。这是最大杠杆点。

## 三、新增分析层(现有抽取缺的"时间轴 / 技法"维度)

现有抽取是"快照式"(实体表/伏笔表/世界规则),**缺时间轴与技法曲线**。新层沿用现有约定(MODEL_FAST 逐批扫 verbatim → MODEL_STRONG 聚合成卡;JSON-in-text + json_repair;白名单模型走 json_schema strict),按书存进**该书 novel.db 的新表**:

- **chapter_beat(每章节拍表 · 最核心)**:`tension_level(0-100) / scene_type(铺垫·小高潮·大高潮·热血·悬疑惊悚·煽情·日常·转场) / pov_holder / is_protagonist_pov / plot_function(setup·escalation·payoff·twist·breather) / hook_type(章末钩子类型) / cliffhanger_strength / new_info`。聚合 → **张力曲线 + 场景类型分布 + 高潮节律(小高潮间距、大高潮位置)**。这是 UC4 的地基。
- **pov_event(视角调度)**:每次 POV 切换 `{to_pov, why_switch(悬念·群像·反派铺垫·信息差), chapters_away_from_protagonist, return_trigger}`。聚合 → "何时离开主角、离开多久、靠什么拉回"的规则。
- **golden_finger_step(金手指升级曲线)**:锚定主角,逐章追踪能力/资源台阶 `{power_tier, new_capability, trigger(机缘·危机倒逼·敌人馈赠), gap_vs_antagonist}`(输入信号复用现有 `entity_states` 境界 diff)。聚合 → 升级斜率 + 每次升级前的铺垫长度 + 与大高潮的对齐。
- **relationship_event(关系演变时间轴)**:补现有 `relationships` 快照之不足,记轨迹 `{from, to, chapter, state(萍水相逢·结盟·恋人·反目·背叛·忠贞·宿敌), transition_trigger}`。聚合 → 关系转换图谱 + 每种转换的典型铺垫手法。
- **worldview_reveal(世界观铺垫技法 · 反信息倾倒)**:`{concept, reveal_method(对话带出·场景浸入·冲突暴露·旁白点到), is_infodump, setup_to_payoff_gap}`。聚合 → 江南式"分章喂设定而不 infodump"的节奏。
- **analysis_card**:上述各层的 MODEL_STRONG 聚合卡(可拼进生成期 system / 前端展示)。

## 四、跨书融合产物(Phase 3+,存 project.db)

- **fused_worldview**:N 本书的 `world_rules` + `setting_register` + `register_card` → MODEL_STRONG 提炼"共同母题 + 可融合设定骨架 + 冲突项调和" → 融合世界观卡(克苏鲁+维多利亚+蒸汽朋克+悬疑)。
- **fused_style**:N 本 `StyleProfile.profile_json` + `scene_exemplars` → 融合声音/POV/节奏卡 + 跨书范文池。
- **technique_template(导演手册)**:N 本各分析层抽象成可复用模板 —— `pacing_curve`(张力节律函数)/ `pov_schedule`(切换规则)/ `golden_finger`(斜率)/ `relationship_arc`(转换菜单)/ `worldview_reveal`(铺垫节奏)。是 UC4 的产物,也是 UC1/3 生成时的可选叠加。

## 五、4 用例 → 具体 pipeline

生成段统一收敛到:**产物塞进 compose 虚拟书 → set_active → `arc.run_arc → outline.refine → draft.write_chapter`**,差别只在"塞什么进去"。

- **UC2(最简,Phase 2)**:虚拟书 = A 的 `style_profile` + 26 类笔法卡,`mimic_enabled=1`;世界观/人物 → 用户大纲走 `outline.refine` 的 user_hints,或"重述 B"→ 把 B 的 `_gather_context`(伏笔/人物/剧情)当骨架;`draft.write_chapter` 逐章生成,自动注入 A 文风范文。**几乎零新代码**。
- **UC1(Phase 3)**:`fused_worldview` + `fused_style` 塞进虚拟书 → `arc.run_arc`(user_hints=用户梗概)→ `outline.refine` → `draft.write_chapter`。
- **UC3(Phase 4)**:A/B/C 的 `plot_points` + `relationship_event` → MODEL_STRONG 抽象成"去具体设定的**剧情母核 + 关系网模板**" → LLM 把母核**重锚定**到克苏鲁世界观的实体/术语 → 写进虚拟书的 entities/relationships/plot_points/foreshadowings;style/world = 克苏鲁组融合卡 → 生成。
- **UC4(Phase 2.5)**:`technique_template` 转成**生成期约束** —— 注入 `outline.refine` 的逐章 `pacing/scene_type/pov_holder/word_target`(按学到的张力曲线排布何时铺垫/小高潮/大高潮/切 POV/金手指升级)+ 注入 writer system(铺垫手法、章末钩子范式)。可叠加到 UC1/3。

## 六、数据模型

**project.db(新,聚合层)**

    projects(id, slug, name, intent, use_case, member_book_slugs_json, created_at)
    fused_worldview(project_id, card_json, source_books_json, cost, updated_at)
    fused_style(project_id, card_json, scene_exemplars_json, source_books_json, cost)
    technique_template(project_id, kind, template_json, source_books_json, cost)
      -- kind: pacing_curve / pov_schedule / golden_finger / relationship_arc / worldview_reveal
    compose_book(project_id, cslug, db_path, status)   -- 指向虚拟 book novel.db
    gen_job(project_id, compose_cslug, arc_run_id, projection_id, status, log_json)

**每本书 novel.db(扩展表,沿用 schema_init create_all 自动建)**

    chapter_beat(chapter PK, tension_level, scene_type, pov_holder, is_protagonist_pov,
                 plot_function, hook_type, cliffhanger_strength, new_info_json)
    pov_event(id, chapter, to_pov, why_switch, chapters_away, return_trigger)
    golden_finger_step(id, chapter, power_tier, new_capability, trigger_event, gap_vs_antagonist)
    relationship_event(id, from_entity_id, to_entity_id, chapter, state, transition_trigger)
    worldview_reveal(id, chapter, concept, reveal_method, is_infodump, setup_payoff_gap)
    analysis_card(category PK, card_json, cost, updated_at)

**compose 虚拟书**:复用现有完整 schema(`memory.schema_init.init_schema`),内容是"融合写入"而非抽取。

**存储布局**

    novel-analysis-imitate/backend/data/
      settings.json            # 共享(symlink → ../../../backend/data/settings.json)
      books/<slug>/            # 复用现有 per-book 布局:corpus.txt + novel.db(原始抽取+新分析表)
      projects/<pslug>/project.db
      projects/<pslug>/compose/<cslug>/novel.db   # 虚拟书

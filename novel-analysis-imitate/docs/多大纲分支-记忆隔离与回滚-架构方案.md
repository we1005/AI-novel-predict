## 问题
续写记忆表(entity_states/plot_points/foreshadowings/relationships/mysteries…)当前**只按章号存、无分支列、全书共享**。
多大纲(分支)并行写作时:①分支间实体/伏笔互相污染;②图谱无法按分支看;③无法逐章回滚某分支。

## 已核实事实(代码支撑,非臆测)
- **每本书已是独立 sqlite**:`data/books/<slug>/novel.db`;`db.py` `book_scope(slug)` 用 contextvar 路由、引擎按 slug 缓存。→ 天然的"按分支路由查询"路由器。
- **图谱 API 已支持 `up_to_chapter`**(`graph/api.py` characters/foreshadowings)= 截至某章快照 = 回滚/时间旅行原语已在。
- **Entity 无 `UNIQUE(type,name)`**(仅 index),但 `extract.py:173-197` 建实体按 `(type,name)` 查已有→命中即**复用同一 entity_id + importance 累加**(upsert-by-name)。→ 共享库必串味。
- **后台回灌线程**(`draft/pipeline.py:876-887`)已知"OS 线程不继承 contextvar",显式捕获 slug 再 `book_scope`。→ 分支 slug 只需照此传入。
- **naimitate compose_book** 已验证"派生书复用同 per-book schema"可行。
- `reset_continuation(from_chapter)` 已能按章删续写产物,痛点只是"横跨所有大纲无法隔离"——分支化后天然消失。

## 方案对比(4 选 1)
| 方案 | 本质 | 迁移量 | 回滚 | 隔离正确性 | 结论 |
|---|---|---|---|---|---|
| **A 分支=派生书(db-per-branch)** | 每大纲一个 slug 库,克隆 ch1-56 基线,续写只写自己库 | **极小**(复用 per-book-db + book_scope) | reset_continuation 限定分支库,现成 | 天然零冲突 | **✅ 推荐** |
| B 单库 + branch_id 列 | 8+ 表加 branch_id,所有查询/写入过滤 | 极大(改 8 表 + 所有 projection + extract upsert) | 删 branch×chapter 行 | upsert-by-name 仍撞车,需再给 unique 加维度 | ✗ 得不偿失 |
| C 事件溯源(delta 日志+物化重建) | 每分支 append-only 逐章 delta,按需重建 | 大(新抽象+重写读路径) | 截断日志重建,最干净 | 好 | 过度设计(当前无此需求量) |
| D 逐章快照/COW | 每章 snapshot 整库,回滚=还原 | 中 | 还原快照,简单 | 好 | 存储膨胀,A 已够 |

## 推荐:**分支即派生书(branch-as-derived-book)**
把每条续写大纲物化成一个独立 slug 的 `novel.db`,从原著克隆 ch1-56 基线,续写(ch≥57)只写入自己库。
三诉求统一收敛到已有的 per-book 抽象,新增代码集中在"克隆基线库"+"前端选库"两点。

### 逐条回答用户四问
1. **要不要每个大纲单独 db?** 要,但粒度是**"一个大纲分支 = 一个库"**(不是"一个视图一个库")。共享库因 upsert-by-name 必串味,独立库零冲突且复用现成 schema。
2. **图谱切【原文/大纲A/大纲B】怎么实现?** 图谱页顶加"视角"下拉;切换本质=切 book slug,前端把 branch slug 作参数传给 `/graph/*`,后端 `with book_scope(slug)` 路由。三张子图吃现成 `up_to_chapter`,**projection 零改**。
3. **三视图(图谱/宝物功法/疑点)各需独立 db?** 不需要。它们是**同一套记忆表的三种投影**(图谱←entities/relationships/foreshadowings/plot_points;宝物功法←EntityState items/skills diff;疑点←mysteries),共享一个分支库即可;各建库会造成基线冗余 + 跨表关联(mystery↔entity/foreshadow)断裂,是反模式。
4. **删某分支最新章→回滚?** 分支独立库让回滚成一步:`book_scope(branch_slug)` 内复用 `reset_continuation(from_chapter=N)`——删 chapter≥N 的 ChapterDraft + 全部派生行 + 伏笔 resolved_chapter≥N 置空。因记忆是"按章 append"增量,删第 N 章增量行 = 状态自动回到第 N-1 章末。需补:mysteries 是 whole-book 就地 mutate、无按章增量语义,回滚要按 `last_updated_chapter≥N` 专门处理。

## 分期落地
- **P1 分支物化底座(M)**:`fork_outline_to_branch(orig_slug, outline_run_id)` → 生成派生 slug 目录、文件级克隆原著库、DELETE ch≥57 续写产物回到基线、写 branch 元数据(parent_slug/base_chapter/outline_run_id)。复用 book_paths/list_books/delete_book。
- **P2 分支内写作(S)**:write_book/write_chapter 在 `book_scope(branch_slug)` 下跑;后台回灌线程照 876-887 传分支 slug。
- **P3 图谱切视角(M)**:`/graph/*` 加可选 `book` 参数(默认 active),前端图谱页加视角下拉。projection 零改。
- **P4 逐章回滚(S)**:`reset_branch_from(branch_slug, from_chapter)`;前端分支最新章加"删除并回滚到上一章"(带 dry-run 预览)。
- **P5 mysteries 回滚补齐 + 基线存储优化(L)**:reset 加 mysteries 按 last_updated_chapter 回退;评估基线从"整份克隆"升级为"共享只读基线 attach + 分支只存增量"省盘。

## 风险
- 磁盘:每分支整份克隆基线,分支多会膨胀 → P5 评估共享基线/硬链接 COW。
- 基线漂移:fork 后原著若重跑抽取更新基线,分支不自动同步 → 明确"fork 即冻结基线"或提供 rebase。
- mysteries/CharacterProfile 等 whole-book 就地 mutate 表无干净按章增量语义 → 回滚需专门处理(P5)。
- 前端 `/graph` 多处调用须统一带 book 参数,漏传会串到 active book → 默认兜底 + 统一下发。
- 后台线程不继承 contextvar(已知坑)→ 分支 slug 必须显式捕获。

## 需用户拍板
1. **基线存储**:整份克隆(简单/MVP)vs 共享只读基线+增量(省盘/复杂)。建议先整份克隆。
2. **分支组织**:派生书是否出现在主书列表(与原著平级)vs 折叠为原著下的子分支(需前端分组)。
3. **fork 时机**:显式"把某 OutlineRun fork 成分支"(建议)vs 每个 OutlineRun 自动建库。
4. **基线冻结 vs 可 rebase**:MVP 建议冻结并写清语义。
5. **mysteries 回滚粒度**:就地按章回退 vs 标记需重跑。
6. **是否要跨分支对比视图**(A vs B 图谱并排)——若要,前端需同时加载两个 book scope。

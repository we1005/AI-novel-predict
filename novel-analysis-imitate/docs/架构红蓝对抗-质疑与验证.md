# 架构红蓝对抗:对整体架构的质疑、解决与验证(闭环)

> 这不是一份辩护,而是一次**自我攻击**的记录。
> 我们用多 agent 红蓝对抗,主动找出对整体架构最狠的质疑,逐个查真实代码、给方案、再独立反驳验证——
> 形成「**猜想 → 方案 → 验证**」的闭环。本轮当场修掉了 2 个被复核确认的真实代码硬伤。

---

## 一、为什么这么做(方法论)

单靠人一个个想质疑,既慢又有盲区。所以把"找茬"本身工程化成一条可复跑的流水线(脚本见
`backend/.../workflows`,本仓库以 Workflow 编排):

```
红队(10 视角并行脑暴)→ 归并排序(去重+按威胁度挑 Top10)
→ 蓝队(逐个查真实代码:判定现状/给方案/实测验证)
→ 对抗复核(独立 agent 尽力反驳蓝队的"已解决")
→ 人工综合成本报告
```

- **红队**专攻不同攻击面:评测有效性、抽取真值、文风可分解性、泛化性、生成耦合、成本价值、产品伦理、工程脆性、数据完整性,外加一个"找致命一击"的反身视角。
- **蓝队**必须**实地读代码**给 `file:line` 证据,不许臆测;能跑 grep / 小脚本就跑。
- **对抗复核**对每个"已解决"独立反驳,给最终裁定 + 残留风险 + 置信度。

本轮规模:28 条原始质疑 → 10 个核心挑战 → 31 个 agent、约 209 万 token、19 分钟。
(诚实记录方法本身的不完美:10 个红队视角有 3 个没产出合规结构化结果,但其余 7 个已足够覆盖。)

## 三、本轮已修复(闭环闭合:不止提方案,且修+验证)

### C6 · render_spec 词汇层是死分支(置信 0.99)

- **质疑**:`render_spec()` 渲染"用词范式"时读 `lex.get("categories")` 和 `c["example_phrases"]`,但 `layer_lexicon()` 产出的是 `strata[].signature_words / gloss / collocations`(`style_genome.py:82-86`)。键名对不上 → **"用词范式"段恒为空,L1 词汇层从未进入喂给 writer 的 system-prompt**。
- **影响**:动摇"基因组 lexicon 维 +7.0"的因果链——若 L1 没进 prompt,这个优势要么另有来源,要么是噪声。也使"逐层消融"失真(关掉一个本就没渲染的层当然不掉分)。
- **修复**:改读 `strata`,输出 `gloss/signature_words/trigger_context/collocations`(`style_genome.py` render_spec)。已验证:渲染含 strata 的基因组后,"用词范式"段非空且正确。
- **残留**:修复后应**重做一次消融**,确认"lexicon +7.0"是否真来自该层(详见第四节评测重做)。

### C8 · 后台笔法抽取未绑 book_scope,跨书污染(置信 0.95)

- **质疑**:`POST /craft/extract` 用 `background.add_task(extract_all)` 起后台线程,既不传 slug 也不包 `book_scope`(`backend/app/craft/api.py:17-21`);`extract_all` 执行时才靠全局 active 指针解析当前书。用户启动抽取后**立刻切书**,后台后续写入全落进新书的库。简报记载此前真实发生过"余烬之铳笔法卡混进九州库"。
- **修复**:请求线程先 `library.get_active()` 捕获当前书 → 传给后台任务 → `extract_all` 内 `with book_scope(slug)` 进程级绑定(`api.py` + `craft/pipeline.py`)。已验证:`extract_all` 新增 `slug` 形参、api 捕获 active、导入正常。
- **说明**:此修触及墨笔 `backend/app/craft/`。"零改墨笔"是指**墨析集成时不改墨笔**,并非禁止修墨笔自身的真实数据完整性 bug;此 bug 同时危害两个项目的风格基准,值得修。
- **残留**:`rebuild_cards` 端点是同步执行(请求线程内),窗口仅秒级,暂留;如需可一并改为后台+book_scope。

## 四、最重要的开放问题:评测可信度(C1/C2/C3/C5)

这四条合起来是本轮**最有价值的发现**——它们说明:**"基因组 65.25 vs 基线 56.75"这个数字,目前撑不起"架构有效"的强结论。** 必须用更硬的实验重新赢回它。具体:

- **C1 循环论证**:`compare()` 的分布维(metaphor_vehicle_dist / hook_grammar_dist / scene_mix / lexical_density)直接取自基因组各层的 LLM 抽取产物——即"用来证明基因组好的尺子,是基因组自己造的"。基线用另一套(StyleProfile 单段总结),评测时却用基因组的尺子量,B 天然占优。
- **C5 死路径**(实地新发现):评测主链 `genome_eval.run_eval` 的"客观对账"其实**只调用 `fingerprint_from_text` 的 3 个正则维**(hedge/redup/ellipsis);`compare()` 那套 20-30 维**在主链根本没被调用**。而 65.25 那套数字来自**另一条** 7 维 LLM 盲评线。所以"循环"和"盲评"是两条独立的线,且宣传的"指纹对账"落地只有 3 维。
- **C2 统计功效**:4 个 brief、每个 A/B 各 1 稿、单评委、无重采样/CI/配对检验。8.5 分差完全可能是噪声 + 评委对"看起来更结构化的稿"的系统性偏好。
- **C3 无人类真值**:全库 grep 评测代码无任何 human/expert/kappa——是"LLM 评 LLM",外部公信力为零;且 LLM 评委可能感知到稿件来自分层 spec,盲性被破坏。

**统一行动方案(优先级高,预计数天)**:
1. **接通并扩维** `compare()`:主链真正调用它,补 `paragraph_granularity / pov_switch_frequency / anachronism_density` 等**与基因组 prompt 无关**的纯代码维。
2. **独立尺子**:用一套与基因组层定义无关的维(平均句长分布/段落熵/对白占比/时代穿帮计数)重算偏差,看 B 优势是否蒸发。
3. **冒充测试**:把 3 段**原著真文**当生成稿喂进 `compare()` 与盲评——若 fidelity 不接近满分 / 真文得分低于生成稿,说明尺子本身有系统偏置。
4. **重采样 + 多评委 + CI**:每 brief 5-10 次、2-3 个评委模型、配对检验或贝叶斯;评委敏感性测试(同稿换 label 看分数漂移)。
5. **(可选)人工真值**:招 5-10 名熟悉原著的编辑做逐维 checklist,算 inter-rater kappa。

> 这正是"如何证明不是过度设计"的硬核版:**先把自己的评测打穿,再用独立、可证伪的尺子重新赢回结论。** 在重做之前,65.25 应被视为"待复核",而非定论。

## 五、设计层开放问题(需要更大改动或实验)

- **C4 格式塔/可分解性**:风格未必 = L1+…+L7 可加。验证法:对比"整段→整段 LLM 改写(不分层)"vs"分层拼装",并比较"整体盲评分"与"7 单维分算术平均"之差;若整体显著更低(>5pt),交互损失坐实。轻量缓解:render_spec 改成**按 scene_type 条件化组织** L1–L5(而非各层独立拼接),先吃掉一部分层间协同。
- **C7 伪融合**:主融合路径 `fusion.build_fused_style` 是 LLM 蒸馏(非纯拼接),但**无显式冲突消解**,且发现 `荆棘王座` 的 `scene_exemplars` 为空(上游抽取缺陷)→ 巧妇难为无米之炊。行动:先补上游 profile 完整性 → 提示词加冲突感知 → 用风格对立的书对做 fidelity 对标(融合组应在两源特征上**均升**而非中庸化)。注:另有一个 MVP 路径 `_voice.fuse_style_summaries` 确为字符串拼接 + `set_active`(非 book_scope),建议废弃或对齐。
- **C9 窗口期假设**:基因组假设"弱模型需 7 层显式指导"。但基线其实已含 exemplar,真正该测的是"**强模型 + 更多 exemplar 直塞** vs 基因组",再加一组"强模型 + 基因组 spec"消融,看 delta;若 delta<3 分,基因组相对 few-shot 的差分价值在强模型下消失,需重新定位(从"生成增强"转向"分析/评测资产")。
- **C10 题材过拟合**:L5 假设线性节拍、L6 显式丢弃负跨度伏笔(`macro_arch:185-186`,无法刻画倒叙)、L7 只有一阶转移。对网文多线/非线性/升级体系表达力不足。行动:L6 补 `reverse_span`、L7 补二阶矩阵、L5 支持并行多线,并补一组非克苏鲁(网文/言情)评测。

# 数字占比 vs 自然语言:文风基因组是过度设计吗?

> 本文用实验数据(而非辩护)回答一个尖锐的质疑,并据此对架构做了一处实证修整。
> 全部实验脚本与原始结果见 [`experiments/`](experiments/),用项目自带的确定性指标度量,不依赖 LLM 评委。

---

## 一、要回答的问题(用户提出)

> 如何证明我们的架构不是过度设计?
>
> 目前文风基因组把各个词汇的占比/密度参数(如 0.42/千字)喂给大模型作为仿写指令。
> 现代大模型已经很擅长理解自然语言("多一点悬疑,少一点龙傲天"),
> 我们凭什么相信"带数字的占比描述"会比"普通自然语言描述"更好?用数字传递信息这种做法,真的更优吗?

这是一个完全正当的质疑。如果数字并不比自然语言传递得更准,那把文风拆成一堆小数点参数就是炫技式的过度设计。
所以我们没有辩护,而是把它当成一个**可证伪的命题**去测——而且用基因组自己的尺子来测。

---

## 二、一句话结论(TL;DR)

**质疑在"prompt 表达力"这一层基本成立,但它打不到基因组的要害——因为基因组其实并不靠"把数字喂给写作模型"工作。**

拆成三句:

1. **把精细数字写进生成 prompt,并不比自然语言更好。** 实验显示 LLM 根本不能精确兑现 prompt 里的"每千字 X 处":结果非单调、方差极大、低值常直接清零;校准过的自然语言在粗粒度分档上至少相当,某一轮甚至更干净。
2. **而我们的代码本来就没这么做。** 审计 `render_spec()`(真正喂给写作 LLM 的那段 system-prompt)发现:它通篇是**定性范式 + 逐字锚点 + 硬约束**,词汇层只给"常用词表 + 例句",**没有把 0.42/千字 这类密度数字写进 prompt**。那个 0.42 是 `/genome` 页面和保真度评测里用的**测量值**,不是生成指令。(还顺手抓到一处想把张力数字写进 prompt 的**死代码**,键名写错,十个月没人发现——因为数字本来就不驱动生成。)
3. **数字真正不可替代的价值在测量侧,不在 prompt 侧。** 只有把文风量化成指纹向量,才能算保真度、做消融、跑 A/B、回归测试、闭环回灌——这些是"多点悬疑"这类自然语言**永远给不了**的能力。这才是基因组不是过度设计的理由,也正是它让整个项目"可被证伪",而不是凭感觉。

换句话说:**量化是为了"测量与控制回路",不是为了"把数字当形容词塞进提示词"。** 基因组(基本上)已经在遵守这条线。

---

## 三、我们怎么验证的

文风基因组里有几个量本身就是**确定性可测**的(见 `_fingerprint.py`),这让"数字到底有没有用"可以被客观检验,无需人类或 LLM 评委:

- 弱断言密度 `hedge/kchar` = 正则 `似乎|仿佛|如同|宛如|好像|大概|也许|约莫` 命中数 ÷ 字数 × 1000
- 词汇密度 `lex/kchar` = 指定词表 `str.count` 之和 ÷ 字数 × 1000

实验思路:**同一题材、同一模型(mimo-v2.5)、同样约 500 字**,分别用「数字设定值」和「自然语言档位」去控制上面的可测量,再用上面这把正则尺子量产出,看谁更能命中目标、分辨率更高。结果可能任意一边赢——下面如实记录,包括对我们不利的部分。

---

## 四、实验与真实数据(三轮)

### 第一轮 · 开环设定(2 轴 × 3 档 × 3 样本)

| 轴 | 档位(目标/千字) | 数字设定 实测均值 | 自然语言 实测均值 |
|---|---|---|---|
| 弱断言 | 低 1 / 中 5 / 高 10 | 2.0 / 2.9 / 13.4(单调) | 0.5 / **21.3** / 28.8 |
| 词汇密度 | 低 2 / 中 8 / 高 16 | 10 / 27 / 17(非单调) | 0.5 / 29 / 7(非单调) |

弱断言轴上,自然语言档位"偶尔使用"竟冲到 **21/千字**(比数字"高档"还高)——这一轮数字看起来更可控。但词汇密度轴上**两者都乱**:一旦在指令里列出生动词表,这个"内容先验"就压倒了任何密度说明。

### 第二轮 · 闭环纠偏(4 样本,目标 5/千字)

模拟系统里 `compare()→回灌` 的真实机制:同一段超标初稿(均值 19/千字),分别用**数字反馈**("当前 X 处,目标 5 处,请改写")和**自然语言反馈**("模糊措辞太多,请明显减少")去纠正。

结果:**两者几乎全部塌到 0.0**。"减少"指令让模型过度纠正、把弱断言清空,数字"5"也没被精确兑现。数字平均偏差 5.0,自然语言 4.62——**无差异,都失败于"精确放置低频次"**。

### 第三轮 · 开环确认(6 样本,自然语言用尽力校准的 steelman 措辞)

| 方法 | 三档实测均值(/千字) | 单调? |
|---|---|---|
| 数字设定(目标 2 / 6 / 12) | 3.1 / 11.1 / 10.6 | **否**(6 与 12 都≈11,部分样本塌到 0,标准差最高 11.1) |
| 自然语言(几乎不用 / 克制地用一点 / 大量反复) | 0.4 / 16.1 / 27.3 | **是**(干净分出三档) |

这一轮直接**反转**了第一轮的印象:数字非单调、高方差;校准过的自然语言反而干净单调。

### 跨三轮的事实

1. **LLM 不能精确兑现 prompt 里的精细数值**——非单调、高方差、低值清零。它把数字也当成模糊的"少/中/多"档位。这与"前向逐 token 采样、无法预规划总量、tokenizer 打乱字符粒度"的机理一致。
2. **校准过的自然语言在粗粒度有序控制上,至少与数字相当,有时更好。**
3. **数字唯一压倒自然语言之处,是"能被确定性测量"**——而这件事发生在评测侧,不在 prompt 侧。

## 五、代码审计:我们其实没把数字喂给写作模型

用户的前提是"我们把 0.x 占比喂给大模型"。审计真正喂给写作 LLM 的 `style_genome.render_spec()` 后,发现**事实并非如此**:

- **词汇层**(`render_spec` 第 345–350 行)输出的是:`总体用词 / 回避 / 【某层】常用:词表;例:例句`——**纯定性 + 逐字锚点,没有密度数字**。
- **句式 / 修辞 / 类型氛围 / 场景套路 / 宏观编排 / 场景递进**也都是定性描述 + 例句 + 套路文本。
- **硬约束**(去仪表盘化、禁自拆比喻、时代保真、段落颗粒度…)全是自然语言规则。
- 唯一一处想把数字写进 prompt 的是张力行(`张力:均{avg}、约每{N}章一个大高潮`)——但它取的键 `tension_modulation` **根本不存在**(真实键是 `tension_law`),所以这是一段**从不触发的死代码**。没人发现,恰恰因为数字不驱动生成、缺了也没影响。

而所有数字(`lexical_density / hedge_per_kchar / reduplication_per_kchar / tension_avg / scene_mix …`)都老老实实待在 **`fingerprint_vector`(测量侧)**,供 `compare()` 算保真度。

**结论:基因组的工程实现,基本上已经在遵守"prompt 定性、数字测量"这条线。** 那个 0.42 是测量/展示/对账用的量,不是生成指令。

> 本文已据此做一处实证修整:把上面那段死代码改成输出**定性张力走势**(`tension_law.profile`,如"慢热多峰"),而不是原始均值/峰间距——既修了 bug,也明确把"数字留在测量侧"写进注释。

## 六、那数字到底在为什么买单(自然语言给不了的)

把"占比 0.42"当**测量目标 + 评测指标**,而不是**prompt 形容词**,它就有了自然语言根本无法替代的四种能力:

- **可打分(fidelity)**:`compare()` 用余弦 / KL 散度 / 相对误差,把"像不像"压成一个 0–100 的保真度分。"多点悬疑"无法被打分。
- **可对账与消融**:逐维偏差报告("克苏鲁层密度低 40%、弱断言超标 3 倍")能定位问题、逐层关掉看边际贡献。自然语言无法做差。
- **可回归测试**:改了 prompt/模型后,指纹偏差能自动告诉你文风有没有漂移。自然语言只能再请人盲读。
- **可闭环回灌**:偏差报告带可执行修正,接进写→审 gate,让仿写从"开环 few-shot"变成"带文体损失的闭环收敛"。

注意:第二轮实验说明,即便有了数字反馈,LLM 也未必能一次纠到位——所以**数字的价值不是"模型听得懂数字",而是"系统能测量出差距、据此决定是否重写/门控/换策略"**。价值在**回路**,不在那个数字本身的说服力。

## 七、反过度设计判据 + 已落地的修整

把上面提炼成一条可执行、可证伪的判据:

> **一个数字,只有当下游有某个确定性程序真的"测量/消费"它时,才值得保留。**
> **纯粹作为 prompt 形容词、没人测量的数字,应当换成"校准定性档 + 1–2 条逐字锚点"。**

按此判据,现状与动作:

- ✅ `fingerprint_vector` 里的数字——有 `compare()` 消费 → **保留**。
- ✅ `render_spec` 词汇/句式/修辞/套路层——本就是定性 + 锚点 → **符合,无需改**。
- ✅ 张力那段死数字代码 → **本文已改为定性走势**(见第五节)。
- ⬜ 建议(未来):`/genome` 专页与解析视频在展示 0.42 这类数时,标注它是**测量/保真度量**,而非"喂给模型的指令",以免重演本次的理解偏差。

这套"先测、再砍掉不拉车的数字"的做法本身,就是对"是否过度设计"的持续回答:**我们用项目自带的尺子,定期检验每个数字有没有在拉车。**

---

## 八、适用边界与不确定性(不反向过度声称)

红队审查明确提醒:**不能由此反推"自然语言一定比数字好"**。本实验的局限:

- **样本量小**(n=3–6)、**单模型**(mimo-v2.5)、**单题材短文本**、**温度固定 0.9** 引入噪声——任一轮的差异都可能含运气成分。要坐实需 n≥30、多模型、温度扫描。
- **词汇密度轴两轮都失效**(内容先验压倒密度指令),该指标本身不适合下强结论。
- **第三轮自然语言措辞经过人工校准**,可能隐含了对模型分布的事后拟合;对数字档位没有做对称的优化。
- **只测了词汇/频率类数字**。**结构类数字**(张力峰间距、转移矩阵概率)来自确定性算法而非"让 LLM 兑现",作用机制不同,**本实验未覆盖**,不应一并否定。

因此本文的安全声明是:**在 prompt 侧,精细数字并不比校准自然语言更可靠,且 LLM 不会精确兑现它;数字的正当性建立在测量/评测/闭环侧。** 这既承认了质疑的合理内核,也守住了基因组的真实价值边界。

## 十、结论

质疑问得对:**把数字当 prompt 形容词,确实近乎过度设计——LLM 不会精确兑现,自然语言够用甚至更好。**
但这打不到基因组的要害,因为:

1. 我们(基本上)没把数字喂给写作模型——`render_spec` 早已是定性 + 锚点;
2. 数字的位置在**测量与控制回路**,那里它不可替代,也正是它让"文风像不像"从主观感觉变成**可计算、可消融、可回归、可闭环**的目标函数;
3. 我们用一条可证伪的判据("没人测量的数字就降级")持续修剪——本文就当场修掉了一段死数字代码。

**这,就是"不是过度设计"的证明方式:不靠主张,靠一把能反过来量自己的尺子。**

# agentic style-search:是过度设计吗?——三组消融实证

> 议题:对已有小说切分打标签建素材库,写作时让 LLM 调 search tool 检索相似描写来参考。
> 用户要求:辨析是否过度设计 + **保留双轨(push/pull)留作对比**。
> 方法:不直接重构成 pull,先建可对比地基 + 跑决定性消融,用数据裁定。

## 一、先查清的事实(实地读码)
- 现有写作是**纯 PUSH**:编排器在调 writer 前预取素材(scene_exemplar 路由 + FTS 风格召回 + 笔法 few-shot)注入 prompt;writer 无主动检索工具。
- 素材分类设施(`CraftSnippet`:26 类 + subtype + tags_json + representativeness)**存在但三本书全空**——笔法库从未真正抽取过。故"用上 tags_json"暂无数据;当前唯一可检索素材 = **章节正文(chapter_fts)**。
- FTS5 用 **trigram** 分词器:query **必须 ≥3 字**,2 字概念词("建筑/码头")实测**零召回**。已在新基座里用"滑动 3-gram + OR"解决。

## 二、消融设计(`docs/experiments/ablation_search.py`,可复跑)
同一题材、同一模型(mimo-v2.5)、约 600 字 ×(4 主题 × 2 样本):
- **A 无参考**:只给主题直接写(基线)
- **B push**:`search_corpus` 取 top-3 原著片段注入后写
- **C agentic**:先让 LLM 自己决定检索 query(JSON-in-text),再 `search_corpus`、注入后写

度量:结构维指纹 `fidelity`(对原著参考指纹,越高越像,无 LLM)+ 盲评(mimo-v2.5-pro,文风相似+场景质量)。

## 三、结果

| 组 | fidelity(结构维) | 盲评 | 样本 |
|---|---|---|---|
| A 无参考 | 32.0 | 37.9 | 8 |
| B push | 30.5 | **66.7** | 7 |
| C agentic | 31.6 | 45 | 8 |

## 四、结论(诚实,含反例)
1. **检索参考有用——但只在盲评显现**:push 把盲评 +29(37.9→66.7);**结构维 fidelity 三组几乎相同(30–32),分不开**。两尺打架 → 结构维是粗代理,holistic"像不像"它捕捉不到(呼应评测可信度文档:需更强尺子 + 人审)。
2. **agentic 未优于 push,反更差**:C 盲评 45 < B 66.7,且多一次 LLM 调用、命中更少(2<3)。实测主因:agentic 的"决定查什么"那步**只把主题原样当查询**,没产出更聪明的子查询。→ **当前实现与规模下,agentic = 更慢 + 更差 = 过度设计。**
3. **对 B 有利结论的混淆项 —— 已校验排除**:做了重合度校验(`ablation_overlap.py`):push 产出 vs 注入参考的平均最长公共子串 6.1 字、≥8字片段覆盖率 **1.2%**;对照组 plain(没看参考)为 2.9 字 / 0%。即 **push 的高分不是照抄,是真风格迁移**(最严重一例抄 18 字,整体可忽略)。保留:本次注入的是短 FTS 片段(~134字),若改注入整段原文,照抄风险升高,需重测。
4. **适用边界**:n=7–8、单评委、单书(余烬之铳)、4 主题、agentic 查询生成偏弱。结论限"**此实现、此规模**"。

## 五、决定(保留双轨)
- **PUSH 留作默认/基线**:检索参考(push)对盲评有实打实增益、成本低 → 值得保留并接进写作(且已修自我污染:`draft` 风味召回排除已生成章)。
- **agentic PULL 暂不建**:就现有证据它是过度设计(慢且不更好)。基座 `craft/search.py` 已留好接口,要建也是 opt-in 实验模式,不替换 push。
- **要翻案 agentic,需先满足**:① 更强的查询生成(多子查询 + 迭代精化,而非回显主题);② 解决检索底座弱(中文语义检索/向量层补活,现 AUC~0.73);③ 仅在 push 路由失灵的场景(多主题混合/跨书融合)对比。

## 六、下一步(可证伪)
1. **持久化产出 + 逐字重合度**:消融保存每段文本,算与注入参考的 n-gram 重合,验证 B 的高分是否靠照抄(防自我抄袭)。
2. 更大 n + 多评委 + 人审锚定(对接评测可信度方案)。
3. 若要给 agentic 公平机会:强化 `arm_agentic` 的查询生成,再比。

> 一句话:**素材库+push 检索参考值得留;agentic 自取在当前证据下是过度设计。** 这正是"保留双轨、用同一把尺子量"得出的、而非拍脑袋的结论。

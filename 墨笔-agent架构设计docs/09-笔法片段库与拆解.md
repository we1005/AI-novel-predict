# 09 · 笔法片段库与风格拆解(Craft Snippet Library)

> 状态:**MVP 已实现**(三类:combat/dialogue_subtext/hook)。本文件定义"按类提取
> 原著笔法片段 + 逐类风格拆解"的功能。与既有 `style.exemplars`(单一分场景范文)同源升级。
> 实现:`app/craft/`(pipeline+api)、`llm/prompts/craft.py`、模型 `CraftSnippet/CraftStyleCard`、
> 前端 `/craft` 页 + 侧栏「笔法拆解」、写作注入见 `draft/pipeline._scene_exemplar_block`。
> 分类用 `MODEL_FAST`、拆解用 `MODEL_STRONG`;全书逐批串行(防 429)。

## 一、目标与定位

把原著按**笔法类别**(打斗 / 对话 / 景物 / 钩子……)拆成片段,**每类留全部条目**
(不只 top-K),并对每一类做风格拆解(句式/节奏/修辞/信息释放/正反例),用于:

1. **给人看**:侧栏新增「笔法拆解」页,按类陈列原著片段 + 每类风格卡,供作者研究。
2. **给写作 agent 用**:按**场景类型路由**注入对应类别的高分片段做仿写 few-shot
   (打斗章注入打斗范式、景物章注入景物范式、章末用钩子范式),比现状单一
   `scene_exemplars` 精准。

定位:它是"文笔风格"模块(`/style`)的细粒度延伸,**不替代** `style_profile`
(宏观画像),而是补全"分类微观范式 + 全量样本库"。

## 二、为什么放进现有 per-book `novel.db`(不单开 SQLite)

- 片段库是**本书派生、且要与 `chapters`/`entities` JOIN、并喂给写作 agent**,放
  同一库最顺(沿用一书一库、同一套备份/重建/切活跃书逻辑)。
- 体量不构成问题:120 万字的书全量打标也就几千行 × 每行几百字 ≈ 数 MB,SQLite 无压力,
  足以"留全部条目"。
- 需要片段全文检索时,在同库加 FTS5 虚表(仿 `chapter_fts`),仍不必单开库。
- 单开 SQLite 仅在"跨书共享"或"超大"时才划算,本场景都不符合。

## 三、数据模型(新增表,均在 per-book `novel.db`)

```
craft_snippet
  id              INTEGER PK
  category        TEXT      -- 见 §四 的类别枚举(如 'combat_duel'/'dialogue_subtext'/'hook_chapter_end')
  subtype         TEXT      -- 细分(打斗:duel/melee/war;对话:君臣/敌对/情感…),可空
  chapter_number  INTEGER   -- 来源章节(FK→chapters.number)
  char_start      INTEGER   -- 在 corpus 中的偏移(便于回溯/高亮),可空
  char_end        INTEGER
  excerpt         TEXT      -- 片段原文(本地私有语料、仅作仿写参考,与 scene_exemplars 同性质)
  representativeness INTEGER -- 典型性评分 0-100(few-shot 优先取高分;但条目全留)
  tags_json       TEXT      -- 该片段的细粒度标签(修辞/节奏/情绪等)
  notes           TEXT      -- 单条点评(可空)
  created_at      TIMESTAMP

craft_style_card           -- 每"类"一张拆解卡(聚合层)
  id              INTEGER PK
  category        TEXT UNIQUE
  snippet_count   INTEGER
  card_json       TEXT      -- 见 §五 拆解维度
  updated_at      TIMESTAMP
```

- "留全部条目" = `craft_snippet` 不做 top-K 截断;`representativeness` 只用于
  **消费端排序**(few-shot 取高分)与前端默认排序,**不删低分条目**。
- 可选 `craft_snippet_fts`(FTS5,content=excerpt)支持片段检索。

## 四、类别枚举

MVP(本期实现)三类:
- `combat`(打斗)—— subtype: `duel`(单挑)/ `melee`(群战)/ `war`(大规模战争)。三者写法差异大,必须分。
- `dialogue_subtext`(潜台词/留白型对话)—— 江南标志笔法,最具仿写价值。
- `hook`(章节钩子)—— subtype: `opening`(开篇钩子)/ `ending`(章末钩子)。

## 五、风格拆解维度(每类 `card_json` 统一结构)

```
{
  "category": "...",
  "summary": "一句话概括该类的总体笔法",
  "sentence_rhythm": "句长分布/短句堆叠 vs 长句铺陈/停顿习惯",
  "rhetoric_density": "比喻/通感/排比 等修辞的频率与偏好",
  "pov_person": "视角与人称习惯",
  "info_pacing": "信息释放速度(慢热/碎匀/爆发)",
  "signature_vocab": ["该类高频词/意象"],
  "structure_template": "典型起-承-收模板",
  "avg_chars": 0,
  "do": ["该这样写的要点"],
  "dont": ["该避免的写法(可对接 pitfalls)"]
}
```

`card_json` 即可直接拼进写作 agent 的 system prompt(按场景类型选对应卡 + 高分 few-shot)。

## 六、抽取管线(吸取教训 #20 输出瓶颈 / #28-#30)

两段式,省 token 且可全量留存:

1. **分类打标(便宜模型,逐章/小批)**:用 `doubao-lite`/`qwen-flash` 扫每章,
   把段落归入类别 + 细分 + 初步 `representativeness`,落 `craft_snippet`。
   小批(按体量自适应,复用 `/ingest/recommend-batch` 思路)以防输出截断漏标。
2. **逐类拆解(强模型,聚合)**:每类取其全部(或高分子集)片段,产 `craft_style_card`。
3. **健壮性**:JSON-in-text + json_repair + 围栏剥离(同 outline/style);失败单类
   降级、不连累其它类;并发受限以避免 429(单批串行更稳)。

抽取入口:侧栏「笔法拆解」页一键触发(可选"全量重抽 / 增量补抽某类")。

## 七、接入写作链路

- 写作前按本章场景类型(已有 scene 路由)选 `category` → 取该类 `card_json` +
  `representativeness` 最高的 N 条 `excerpt` 作 few-shot 注入 writer system。
- 章末生成时,用 `hook/ending` 卡 + 范例强化"强钩子"(对接现有 ending_hook 短板)。
- mimic 开启时绑定;关闭时该注入跳过。

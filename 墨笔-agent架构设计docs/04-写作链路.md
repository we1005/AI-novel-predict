# 04 · 写作链路（Outline + Draft）

> 从「**phase 大纲**」到「**章节正文**」。中间是经典的 Writer + 多 Reviewer + Editor + ReAct 重写循环。

> **🔄 实现现状（2026-06 更新）**：
> 1. **OutlineAgent 改 JSON-in-text**（同预测链路；贴 schema、无 forced tool、`json_repair`），并新增 `chapter_start/end override`、`continuity_hint`、`persist` 参数供[整本推演](./07-整本故事弧推演链路.md)驱动。
> 2. **门控从"Editor 自由裁决"改为确定性 lane 门控**：文风审查只作建议（**永不触发返工**，避免在"太华丽/太碎"间反复横跳耗尽预算），只有 **plot / consistency 的硬伤**才强制 revise；用尽轮次保留最干净一稿。根因见改进记录"文风审查横跳"。
> 3. **模型路由（多服务商）**：Writer/Outline → `minimax-m3`（散文最佳）；三审 + Editor → `doubao-seed-2.0-lite`（便宜稳）。
> 4. **仿写模式**：开启「模仿原作者文风」时，Writer 系统提示由 `build_writer_system(mimic_guide)` 注入作者文风画像（见文笔风格链路）。
> 5. **空输出自动重试**：客户端层若返回空正文且无工具调用即重试（最多 3 次），全 agent 通用。

## 1 · 端到端流程

```
arc/predict winner
       │ (source_kind, source_run_id, chosen_index)
       ▼
┌──────────────────────────────────────┐
│ /outline/refine                      │
│  OutlineAgent (T=0.6, MODEL_STRONG) │
│  → 把 phase 拆成逐章 outline 列表    │
│   (chapter_index, title, must_include,│
│    pov, conflict, target_chars, ...) │
└──────────────────────────────────────┘
       │
       ▼
OutlineRun.chapters_json[]
       │
       ▼
┌──────────────────────────────────────┐
│ /draft/write                         │
│  per chapter, ReAct 最多 3 轮:       │
│  [Writer]                            │
│   ↓                                  │
│  [Style Reviewer] [Plot R.] [Cons. R.]│
│   ↓ (并行) ↓ (并行) ↓ (并行)         │
│  [Editor] → approve / revise / ship  │
│   ↓ revise (with revision_brief)     │
│   loop back to Writer                │
└──────────────────────────────────────┘
       │
       ▼
ChapterDraft.final_text
```

## 2 · OutlineAgent

**文件**：`backend/app/outline/pipeline.py::refine`
**Prompt**：`llm/prompts/outline_refine.py::OUTLINE_REFINE_SYSTEM`

输入：从 arc / predict 选定的 phase（含 `chapter_range`、`summary`、`must_include_foreshadow_ids`）。

输出 schema：

```jsonc
{
  "chapters": [
    {
      "chapter_index": 1473,
      "title": "...",
      "pov": "林云",
      "must_include": ["与莱恩对峙", "回忆三章前的预兆"],
      "conflict": "...",
      "tone": "悬疑 / 战斗 / 文戏",
      "target_chars": 3500,
      "open_loops": ["..."]    // 章末留白
    }, ...
  ]
}
```

- **`must_include`** 是写作时给 Writer 当 must-have 清单
- **`open_loops`** 是给下一章的钩子（防 outline 写成"流水账每章自闭合"）
- **arc_meta** 注入：如果上游是 arc 模式，还会把全弧的"phase 之间的承接"作为不可违背约束塞进 system

T=0.6（不同于 prediction 的 0.95）——大纲求结构稳定，不是发散。

## 3 · Writer（第一稿生成）

**文件**：`backend/app/draft/pipeline.py::_writer_call`
**Prompt**：`llm/prompts/writer.py::WRITER_SYSTEM`

```python
resp = llm.call(
    agent="draft.writer",
    model=MODEL_STRONG,
    system=[WRITER_SYSTEM, *cached_blocks],   # 同 predict 的 6 个 ctx blocks
    messages=[{"role": "user", "content": user}],
    max_tokens=8000,
    temperature=0.75,
)
```

`user` 由 `build_writer_user_message` 构造，包含：
- 本章 outline 全文
- 风格参考片段（`_gather_style_refs` 用 must_include 关键词走 FTS 召回最近章节）
- 是否 revision（如果是第 2-3 轮，附上 `revision_brief` + `failed_issues_quoted`）

输出是**纯文本**（不走 tool_use）——正文该是文字就是文字，不该套 JSON。

## 4 · 三个并行 Reviewer

**文件**：`pipeline.py::_reviewer_call`
**Prompt**：`llm/prompts/reviewers.py`

```python
review_jobs = [
    ("style",       STYLE_REVIEWER_SYSTEM,       STYLE_REVIEWER_TOOL),
    ("plot",        PLOT_REVIEWER_SYSTEM,        PLOT_REVIEWER_TOOL),
    ("consistency", CONSISTENCY_REVIEWER_SYSTEM, CONSISTENCY_REVIEWER_TOOL),
]
with ThreadPoolExecutor(max_workers=3) as ex:
    futs = {ex.submit(_reviewer_call, ...): name for ...}
    for fut in futs:
        reviews[name] = fut.result()
```

| Reviewer | 关注 | 典型 issue.severity |
|---|---|---|
| **style** | 节奏 / 句式 / 视角切换 / 文风偏离作者腔 | suggestion / minor |
| **plot** | 是否遵 outline / 高潮位置 / 戏剧张力 | major / blocker |
| **consistency** | 与 entity_state / world_rule / 已 plant 伏笔的冲突 | blocker / major |

**所有 Reviewer 共享同一份 `cached_blocks`**——这就是 cache 大额省钱的地方：3 次并行调用，输入 token 只算一份。

输出 schema：

```jsonc
{
  "issues": [
    {
      "severity": "blocker | major | minor | suggestion",
      "category": "style|plot|consistency",
      "quote": "原文中的具体片段",
      "problem": "...",
      "suggested_fix": "..."
    }
  ],
  "overall": "一段话总评"
}
```

## 5 · Editor（仲裁）

**文件**：`pipeline.py::_editor_call`
**Prompt**：`llm/prompts/reviewers.py::EDITOR_SYSTEM`

Editor 看 3 个 reviewer 的输出，决策：

```jsonc
{
  "decision": "approve | revise | ship_with_warnings",
  "rationale": "...",
  "merged_issues": [...],     // 去重并按 severity 排序
  "revision_brief": "..."     // decision==revise 时给 Writer 的修改清单
}
```

**Editor 失败保底**：如果 Editor 调用失败（罕见），落到 `heuristic_decision()`——纯逻辑：blocker > 0 → revise；attempt == max → ship_with_warnings。

## 6 · ReAct 循环

```python
for attempt in range(1, max_attempts + 1):       # 默认 max=3
    prose = _writer_call(..., previous_attempt=prev_feedback)

    if skip_reviews:                             # 用户可选跳过审查
        return prose

    reviews = {3 reviewers in parallel}
    editor = _editor_call(reviews, ...)

    if editor.decision in {"approve", "ship_with_warnings"}:
        return prose                             # 出稿

    prev_feedback = {
        "prose": prose,
        "revision_brief": editor.revision_brief,
        "failed_issues_quoted": [i for i in merged if severity in {blocker, major}]
    }
else:                                            # 用尽 max_attempts
    return last_attempt + "shipped_with_warnings"
```

每轮的 `prose / reviews / editor` 全部写入 `ChapterDraft.attempts_json`，可在 `/draft` 页一字不漏回看。

## 7 · 模型温度速查

| 角色 | model | T | 理由 |
|---|---|---|---|
| OutlineAgent | STRONG | 0.6 | 求结构稳定 |
| Writer | STRONG | 0.75 | 兼顾创意与稳定 |
| Reviewer × 3 | FAST | 0.2 | 评审要可重现 |
| Editor | FAST | 0.2 | 仲裁应该确定性 |

## 8 · 成本与时间

实测一章 (~3500 字)，3 reviewer 全开，平均 1.5 轮收敛：

| 项 | 值 |
|---|---|
| LLM 调用 | ~6-9 (writer × 1-3 + reviewers × 3-9 + editor × 1-3) |
| 输入 tokens | ~25-40K（cached 命中后实付 ~8-12K） |
| 输出 tokens | ~5-9K |
| 成本 | ~$0.012-0.025 / 章 |
| 耗时 | ~50-90 秒 |

`skip_reviews=true` → 单 Writer call，~$0.005，~15 秒。

## 9 · 与仿真链路的连接

`/sim/simulate` 产出的 `final_text` 也可以喂回这条链路：把它当作 Writer 第一稿，继续走 reviewer + editor 审查链。这样**仿真章节自动获得风格 / 一致性兜底**。

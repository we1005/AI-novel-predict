# 01 · 上下文记忆模块

> 「LLM 没有记忆，是因为它每次都从空白开始。」我们要做的是给它一个**可索引的、章节有时序的、按需召回的**外部大脑。

## 1 · 四层记忆栈

```
┌────────────────────────────────────────────────────────┐
│ Layer 4 │ Graph Projection (动态生成)                   │
│         │ 把 SQLite 行投影成 React-Flow 节点+边         │
│         │ 文件: backend/app/graph/projections.py       │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ Layer 3 │ ChromaDB (语义召回，懒加载)                   │
│         │ 章节级向量；FTS 召不到时用语义补              │
│         │ 文件: backend/app/memory/vector.py           │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ Layer 2 │ FTS5 (全文检索，trigram tokenizer)            │
│         │ 章节正文 + 实体描述 + plot summary 全索引     │
│         │ 文件: backend/app/memory/fts.py              │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ Layer 1 │ SQLite 结构化表 (主存储)                      │
│         │ 11 张核心表，每条记录带 chapter 字段          │
│         │ 文件: backend/app/memory/models.py           │
└────────────────────────────────────────────────────────┘
```

每一层都对**章节号**敏感：所有事实带 `chapter`、`first_chapter`、`planted_chapter` 等字段，召回时严格按 `<= after_chapter` 过滤——这是防止 agent "知道未来"的物理隔离。

## 2 · Layer 1：核心表设计

| 表 | 字段要点 | 用途 |
|---|---|---|
| `Chapter` | number / title / `char_offset_start/end` | 不存正文，用 offset 切片原文 |
| `Entity` | type / name / role / importance / first_appear_chapter | 人/物/势/法/概念五分类 |
| `Relationship` | from / to / label / first_chapter / status / weight | 关系图边 |
| `EntityState` | entity_id + chapter + state_json + diff_json | append-only 状态快照 |
| `Foreshadowing` | type / planted_chapter / resolved_chapter / status | 伏笔生命周期 (open / resolved / dropped) |
| `PlotPoint` | chapter / summary / importance / involved_entity_ids | 关键节点 |
| `WorldRule` | term / definition / first_chapter | 世界设定术语 |
| `Mystery` | question / category / severity / status / confidence / clues_json | 读者追问的悬念 |
| `CharacterProfile` | bio / desires / fears / voice_style / secrets / arc_so_far | 角色化身（仿真用） |
| `LLMCall` | agent / model / tokens / cost / cache_read | 审计追溯 |
| `ExtractionBatch / PredictionRun / OutlineRun / ChapterDraft / SimulationRun / ArcRun / InterviewLog` | 各 pipeline 的运行记录 |

**关键设计选择**：
- 状态是 **append-only**：不更新行，每章插一条 `EntityState`；想看「林云在第 800 章的状态」就 `WHERE entity_id=1 AND chapter <= 800 ORDER BY chapter DESC LIMIT 1`。
- 伏笔有 **生命周期**：planted → open → (resolved | dropped)；预测时只取 `status='open'` 且 `planted_chapter <= after`。
- Mystery 与 Foreshadow **分两表**：Foreshadow 是作者埋的具体钩子，Mystery 是读者抽象出的"还在追问的问题"。后者跨批维护、可锐化、可被多个 foreshadow 关联。

## 3 · Layer 2：FTS5 全文检索

`backend/app/memory/fts.py` 用 SQLite FTS5 + trigram tokenizer（中文友好）建索引：

- 索引粒度：章节正文（用 char_offset 切片后入库）
- 调用点：
  - 写作时召回**风格参考片段**（Writer 给 must_include 关键词，FTS 找最近 3-5 章里的相关片段）
  - 仿真时 ReportAgent 的 recall 工具
- 查询接口：`fts.search_chapters(query: str, limit: int) -> list[dict]`

**为什么不用 embedding 当主索引？**
中文小说里"火灵根"和"金灵根"在 BERT 类向量里非常相近，语义召回会把它们混在一起，但作者用词是有意区分的。FTS 走字面 trigram 匹配，更尊重原文。语义召回作为补充。

## 4 · Layer 3：ChromaDB 向量（懒加载）

`backend/app/memory/vector.py`：

- 仅在用户访问需要的端点时初始化（`_lazy_init()`）
- 章节级别 embed（不切句），collection_name = `"chapters"`
- 用途：FTS 召不到时（query 是抽象概念而非字面词）

> 实测：目前主要靠 FTS + 结构化表，向量层用得不多。保留是为之后做"角色记忆问答"——比如让林云回忆"我是什么时候开始怀疑莱恩的？"

## 5 · Layer 4：Graph Projection (动态)

`backend/app/graph/projections.py` 把表投影成图谱视图：

| 端点 | 投影 | 前端用途 |
|---|---|---|
| `character_graph(up_to_chapter)` | Entity (person) + Relationship (实体关系 / 共现关系) | `/graph` 人物关系 |
| `foreshadowings_gantt()` | Foreshadowing 时间轴 | `/graph` 伏笔甘特 |
| `hero_arc()` | Entity(主角) 的 EntityState 序列 | `/graph` 主角演变 |
| `hero_items()` | 主角的 item/skill 与 Foreshadow 关联 | `/items` 宝物功法 |
| `timeline()` | PlotPoint 按重要度排序 | `/graph` 剧情时间线 |

投影函数都接受 `up_to_chapter` 参数，做"按时点回放"。

## 6 · Cached Block：上下文复用机制

`backend/app/llm/client.py::cached_block(text)` 把一段文本标记为 prompt cache 候选。同一批次的多 agent 调用（比如 6 个抽取 agent 共享同一段历史摘要）只首次付费 input token。

典型组合：

```python
blocks = [
    llm.cached_block("【未收束伏笔表】\n" + llm.stable_json(open_fs)),
    llm.cached_block("【世界规则】\n" + llm.stable_json(rules)),
    llm.cached_block("【主要人物当前状态】\n" + llm.stable_json(states)),
    llm.cached_block("【近期 5 章标题】\n" + llm.stable_json(titles)),
]
# 6 个 agent 共用 blocks，只第一个付完整 input token，后五个走 cache_read
```

`stable_json` 保证序列化后的 JSON 字符串字典序稳定——cache key 才能命中。

## 7 · 召回管线总图

```
任务请求 (e.g. 预测第 1473 章)
    │
    ▼
_gather_context(after_chapter=1472)        ── predict/pipeline.py
    │
    ├── open_foreshadowings   (status=open AND planted ≤ 1472)
    ├── world_rules           (全部)
    ├── recent_plot           (chapter ≤ 1472, top 15 by chapter)
    ├── recent_chapter_titles (chapter ≤ 1472, last 5)
    ├── characters            (importance ≥ 5, latest state ≤ 1472)
    └── open_mysteries        (status in [open, sharpened, partial], conf ≥ 50)
    │
    ▼
_ctx_blocks(ctx) → 6 个 cached_block
    │
    ▼
LLM agent (system = [agent_prompt, *blocks], user = task)
```

每个 pipeline 的 `_gather_context` 都是这个模板的变体——决定**哪些维度被记起**。

## 8 · 不做的事

- ❌ **跨小说共享记忆**：每本书一个 SQLite 文件，独立。
- ❌ **真实时间戳**：章节号就是时间，不需要 wall-clock。
- ❌ **图数据库**：Neo4j 太重，SQLite + projection 函数已经够用。
- ❌ **embedding 当主索引**：中文长文 trigram > 通用 embedding。

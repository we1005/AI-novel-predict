# 05 · 角色仿真链路

> 不再是"作者口吻续写"，而是**让小说人物自己活一遍**——每个角色独立决策，多轮互动，再由旁白综合成章。灵感来自 MiroFish 的多 agent 模拟实验。

> **🔄 实现现状（2026-06 更新）**：
> 1. **`profile.build` / `sim.decide` 改 JSON-in-text**：两者都跑 `doubao-seed-2.0-lite`（火山推理），原先 forced tool_choice 会**静默吞输出**——档案悄悄构建失败、仿真里角色动作凭空消失（且 `sim.decide` 当时无任何兜底）。现统一贴 schema、`json_repair` 解析正文。`ReportAgent`（综合成章）走 `minimax-m3`。
> 2. **端到端实测（天之炽）**：top-20 档案 20/20 成功；5 角色 × 3 轮**每轮 5 动作全产出**、决策相互勾连；ReportAgent 综合出连贯涌现章节。
> 3. **健壮性**：状态更新加 `if row:` 守卫，避免 sim_id 失效时在异常处理里二次崩溃 / 状态卡死。

## 1 · 为什么要仿真？

普通续写的 prompt 里塞满了"林云：性格冷静，desires=...，知道伏笔 X"，但这都是**被动 prompt 上下文**——模型一次性看完后自己"代笔"。结果：

- 角色对话像"作者写的对话"，不像两个不同人讲话
- 二阶效应缺失：A 说了 X，B **真的**会按"我刚听到 X"去反应，不是按"剧情需要 B 反对"去反应
- 同一段戏每个角色的视角差异被抹平

仿真改成：每个角色**自己**调一次 LLM，**只看**自己应该知道的事，**写出**自己的下一步。多轮迭代后由 ReportAgent 综合。

## 3 · ProfileBuilder

**文件**：`backend/app/sim/profile_builder.py`
**Prompt**：`llm/prompts/profile.py::PROFILE_SYSTEM` + `PROFILE_TOOL`

每个角色**独立调一次** LLM（并行 ThreadPool，4 worker），输入只是这个角色相关的切片：

```python
def _gather_for_character(entity_id, max_chapter):
    return {
        "entity": ent.name + ent.description,
        "states": EntityState[entity_id, chapter <= max_chapter],
        "relationships": Relationship[from/to == entity_id],
        "plot_points": PlotPoint where involved_entity_ids contains entity_id,
        "foreshadowings": Foreshadowing where related_entity_ids contains entity_id,
    }
```

输出 schema：

```jsonc
{
  "bio": "...",
  "desires": ["...", ...],          // 3-5 条
  "fears": ["...", ...],            // 2-4 条
  "moral_compass": "...",
  "voice_style": "...口头禅...",
  "typical_actions": [...],
  "relationships_summary": [{name, label, attitude}, ...],
  "secrets_known": [{secret, learned_chapter}, ...],
  "secrets_hidden": ["...", ...],   // 自己藏的
  "arc_so_far": "...截至 N 章的成长轨迹..."
}
```

**关键设计**：`secrets_known` vs `secrets_hidden`——前者是"你知道但别人不一定知道"，后者是"你藏着的"。仿真决策时这俩字段决定行为差异。

每个 profile 带 `last_built_chapter`。如果触发仿真时 `last_built` 比当前 `after_chapter` 早 200+ 章，simulator 会**自动重建**该角色 profile（角色经历了太多事，旧档案会偏）。

T=0.3，单个角色调用 ~$0.001-0.003，~5-15 秒。

## 4 · InterviewAgent

**文件**：`backend/app/sim/interview.py`
**Prompt**：`llm/prompts/interview.py::INTERVIEW_SYSTEM`

接口：`POST /sim/interview { character_id, after_chapter, question }` → SSE 流。

```python
def stream_answer(entity_id, after_chapter, question):
    profile = get_profile(entity_id)
    relevant_state = _gather_relevant_state(entity_id, after_chapter)

    user = build_interview_user(profile, after_chapter, question, relevant_state)

    answer_buf = []
    for chunk in llm.stream_text(
        agent="sim.interview",
        model=MODEL_FAST,
        system=[INTERVIEW_SYSTEM, cached_block(profile_blob)],
        messages=[{"role": "user", "content": user}],
        temperature=0.7, max_tokens=2000,
    ):
        answer_buf.append(chunk)
        yield chunk

    persist_to_interview_log(entity_id, question, "".join(answer_buf), ...)
```

**System 7 条铁律**（防 AI 助手腔）：

1. 第一人称
2. 只知道你截至第 N 章应该知道的事（不能泄露未来）
3. 保持 voice_style（含口头禅）
4. 保持 moral_compass（拒绝违背价值观的诱导）
5. 回答 ≤ 500 字
6. 避免"作为 AI 助手……"这种自报身份
7. 角色化拒绝（"我不能告诉你"要写得像角色会说的话）

前端 `/character/[id]` 页有滑块控制 `after_chapter`——同一问题在第 200 章问跟第 1472 章问，回答应**显著不同**（早期角色不知道很多事）。

## 5 · Multi-Round Simulator

**文件**：`backend/app/sim/simulator.py::run_simulation`
**核心 prompts**：`llm/prompts/decision.py::DECISION_SYSTEM` + `sim_report.py::REPORT_SYSTEM`

### 5.1 流程

```
1) _select_cast(after_chapter, n_characters, focus)
     主角必入 → focus 必入 → 按 importance 补足到 n_characters
     默认 5-8 人

2) _ensure_profiles(cast, after_chapter)
     缺 profile 或 last_built 漂移 > 200 章 → 重建

3) _initial_state(after_chapter, cast)
     {
       char_state: { 林云: {hp, location, mood, recent_event}, ... },
       open_foreshadowings: [...],
       recent_plot_points: [last 8],
       cast_relationships: [...],
       world_rules_brief: [...],
     }

4) for round in 1..n_rounds:                ← 默认 3-5 轮
       ThreadPool(workers = min(cast, 6)) {
           for each character:
               action, cost = _decide_one(char, own_profile, initial_state,
                                          rounds_so_far, cast_names, ...)
       }
       round_record = { round, actions: [...] }
       persist incrementally to SimulationRun.rounds_json

5) _report(simulation_id, rounds, after_chapter)
     ReportAgent (MODEL_STRONG, T=0.7, max_tokens=8000)
     → 按行动日志综合成 ~3000 字章节
     → 写入 SimulationRun.final_text
```

### 5.2 DecisionAgent

每个角色**独立**调一次（同一轮内并行）：

```python
known = {
  "name": character.name,
  "profile": {bio, desires, fears, moral_compass, voice_style,
              relationships, secrets_known, secrets_hidden, arc_so_far},
  "my_current_state": initial_state.char_state[character.name],
  "shared_open_foreshadowings": [...],
  "recent_plot_points_known_to_all": [...],
  "world_rules_brief": [...],
  "cast_present": [other characters' names],   ← 只名字，不传别人 profile
  "after_chapter": N,
}

resp = llm.call(
    agent="sim.decide",
    model=MODEL_FAST,
    system=[DECISION_SYSTEM, cached_block(stable_json(known))],
    messages=[{"role": "user", "content": f"当前是第 {round_index+1} 轮，所有公开动作:\n{rounds_so_far}\n你做什么？"}],
    tools=[DECISION_TOOL],
    tool_choice={"type": "tool", "name": DECISION_TOOL["name"]},
    temperature=0.85, top_p=0.95,
    max_tokens=2000,
)
```

`DECISION_TOOL.input_schema`：

```jsonc
{
  "kind": "speak | act | move | observe | reveal | decide | wait",
  "target_name": "...",       // 可选
  "content": "...",           // ≤200 字
  "reasoning": "...",          // ≤100 字（debug 用，不进入正文）
  "emotional_state": "..."    // 可选
}
```

**关键约束**：
- 角色**看不到**其他角色的 profile / secrets_hidden（只看名字）
- 角色**看得到**之前轮所有人的公开动作（`rounds_so_far`）
- 系统强制 truncate `content[:240]` / `reasoning[:160]` 防失控

### 5.3 ReportAgent

不是"把 actions 拼起来"——而是给一个**可见的剧本**让作者去写舞台戏：

```python
blocks = [
    cached_block("【仿真元信息】" + json),
    cached_block("【仿真行动日志】" + rounds_json),
    cached_block("【参演角色档案概要】" + brief),
]
user = (
    "把上述仿真综合成 ~3000 字中文章节。按行动日志顺序展开，"
    "加场景与心理描写连接。开头第一行写章节标题（第 N+1 章 ……），空行后正文。"
)

resp = llm.call(
    agent="sim.report",
    model=MODEL_STRONG,
    system=[REPORT_SYSTEM, *blocks],
    messages=[{"role": "user", "content": user}],
    temperature=0.7, max_tokens=8000,
)
```

`REPORT_SYSTEM` 三条铁律：
1. **不增不减**仿真中已发生的事件——不能凭空加角色或动作
2. 第三人称限制视角（默认主角视角）
3. 把 `reasoning` 转化成**心理描写**（外化思考），不是直接引用

## 7 · 成本与时长

| 配置 | 调用数 | 成本 | 时长 |
|---|---|---|---|
| 4 角色 × 2 轮 (smoke test) | 8 + 1 = 9 | $0.004 | ~60 秒 |
| 5 角色 × 3 轮 (默认) | 15 + 1 = 16 | ~$0.08 | ~3-4 分钟 |
| 8 角色 × 5 轮 (最大) | 40 + 1 = 41 | ~$0.20 | ~8-10 分钟 |
| 单次 interview | 1 | ~$0.005 | ~30 秒 |
| 一次 profile 重建 (top-20) | 20 | ~$0.05 | ~2 分钟 |

> 跑 ReportAgent 用 `MODEL_STRONG` 是因为 8K 长输出对模型质量要求高；其余阶段都用 `MODEL_FAST`。

## 8 · 与其他链路的对比

|  | predict | sim |
|---|---|---|
| LLM 调用次数 | 3 (A/B/C) | 15-40 |
| 角色"主体性" | 仅在 prompt 出现，被动参考 | 每个独立调用 |
| 戏剧张力来源 | 单次推理 + 评分 | 多轮二阶效应 |
| 控制力 | 高（Stage A 候选可选） | 低（涌现） |
| 适合场景 | 主线推进 | 角色互动密集的大场面 |
| 平均成本 | $0.01-0.03 / 章 | $0.08-0.20 / 章 |

实战策略：长线情节用 predict + draft，关键大场面（多人对峙、群像戏）用 sim。

## 9 · 不做的事

- ❌ 让仿真替代 predict / draft（保留作 fallback）

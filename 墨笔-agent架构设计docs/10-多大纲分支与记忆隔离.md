# 10 · 多大纲分支与记忆隔离(分支即派生书)

> 2026-07-03 落地。解决:同一本书想沿**多条"整本故事弧候选"**并行续写时,各分支的成稿与"写→回灌"抽取的实体/伏笔必须**彼此隔离**;且某分支写坏了要能**逐章回滚**。

## 一句话结论

**一条"整本故事弧候选" = 一本独立的"分支书"(派生 novel.db)**。分支从原著克隆 `ch1..N` 的记忆作基线,续写(`ch>N`)只写进自己库——天然隔离、天然可回滚,几乎零核心改动。

## 为什么不是"给记忆表加 branch 列"

续写记忆表(`entity_states / plot_points / foreshadowings / relationships / mysteries / world_rules`)**只按章号存**。若多分支共用一个库:

- `extract` 建实体时按 `(type,name)` **upsert 复用同一 entity_id 并累加 importance**(`ingest/extract.py`)——分支 A、B 给"主角"写的境界/宝物会挂到同一 entity_id,`character_graph / hero_items` 按章 diff 时必然**串味**。
- 要隔离就得给 8+ 张表加 `branch_id` + 重写所有 projection 查询 + 改 extract 的 upsert 维度,迁移面极大。

而墨笔**每本书本来就是独立 sqlite**(`data/books/<slug>/novel.db`,`db.py::book_scope(slug)` 用 contextvar 路由、引擎按 slug 缓存),且图谱 projection 已支持 `up_to_chapter` 快照。→ 把分支做成"派生书"正好复用这三件既有资产。

## 数据模型

```
data/books/
├── 姝爻误全集/                       原著(56 章)
│   └── novel.db                     实体/伏笔/关系… 全按章号存
├── 姝爻误全集__剑灵泣血·人间棋局/       分支 = 候选弧 #0
│   ├── novel.db  (克隆自原著 ch1-56 基线 + 续写只写这里)
│   └── branch.json {parent_slug, arc_run_id, chosen_index, base_chapter, branch_name}
└── 姝爻误全集__道源之劫/             分支 = 候选弧 #1
    └── ...
```

- **fork**:`library.fork_book()` 用 sqlite backup API 克隆 `novel.db`(WAL 一致)+ 拷 `corpus.txt`,写 `branch.json`;随后 `book_scope(branch)` 内跑 `reset_continuation(base+1)` 把克隆带来的续写产物清干净,回到纯基线。
- **base_chapter**:原著**真实**正文章数(排除"续写登记的 0-offset 章"),即续写起点 = `base+1`。
- 分支就是一本书 → `set_active(branch)` 后现有写作/推演/抽取/回滚链路**直接落分支库**,无需改造(P2 白送)。

## 三层"切换"(职责不同,勿混)

| 层级 | 入口 | 作用域 | 能否写 |
|---|---|---|---|
| **换工作书** | 书架「切换到本书」(`set_active`) | 全局、持久 | ✅ 续写/推演/回滚都落它 |
| **建分支** | 书架「建分支」/ 推演面板「🌿 把此候选弧建为分支」 | 新建一本派生书 | — |
| **视角预览** | 图谱/宝物/疑点页顶部「视角」下拉(`?book=` 参数) | 仅当前页、临时 | ❌ **只读**,用于并排对比 A/B |

## 逐章回滚(一致性维护)

`draft/pipeline.py::reset_continuation(from_chapter)`——删 `chapter >= from` 的**全部续写产物**,原著(`< from`)一律不动:

- `chapter_drafts`(成稿)+ 各派生表(`entity_states/plot_points/foreshadowings/relationships/craft_snippet` + 续写新登场的 `entities`/`world_rules`)
- `foreshadowings.resolved_chapter >= from` → 置 NULL(伏笔回到"未回收")
- `mysteries/character_profiles` 的章指针 >= from → 置 NULL(整本就地 mutate 表,无按章增量语义,MVP 只清指针)
- 续写登记的 0-offset `chapters` 行(FK 锚点)→ 删(放最后,先清引用它的 FK 行)

因为记忆是"按章 append"的增量,**删第 N 章增量 = 状态自动回到第 N-1 章末**。前端两个按钮:
- 「↩ 回滚最新续写章」`from = 最新续写章号`(只删最后一章)
- 「🧹 重置续写」`from = base+1`(清全部续写、回原著基线)

## API / 前端一览

- `POST /books/fork {parent_slug, branch_name, arc_run_id?, chosen_index?, outline_run_id?, set_active}`
- `GET /books` → 每本书带 `is_branch/parent_slug/branch_name/arc_run_id/chosen_index/base_chapter`(前端据此折叠)
- `POST /draft/reset-continuation {from_chapter, dry_run, book?}`(`book` 可指定分支)
- `/graph/*`、`/mysteries` 加可选 `book` 参数 → `book_scope` 路由(视角预览)
- 前端:书架分支折叠 + 建分支弹窗;arc 推演面板「建为分支」;图谱/宝物/疑点「视角」下拉(`BranchViewPicker`);draft 页回滚按钮。

# 整本故事弧推演链路（Whole-Book Projection）

> 目标：从「当前章 + 1」一次性把后续**整本书**的剧情推演到结局，产出连续逐章大纲 + 完整性裁决。
> 这是在「局部预测（predict 单章）」「整本故事弧（arc 宏观骨架）」「逐章大纲（outline）」之上的**编排层**。

---

## 一、为什么需要它 / 策略决策

把"预测下 1-3 章"上升到"预测整本书"时，两条朴素策略都不够：

| 朴素策略 | 问题 |
|---|---|
| **递归"下 10 章"+ 大模型判断该不该停** | 剧情漂移；伏笔收束不了；停点判断脆弱、易无止境 |
| **一次性生成整本大纲** | 长结构输出在 **tail 退化**——实测旧 arc：phase3 `ch206→199`（end<start 倒挂）、另一条只覆盖估算体量的一半 |

**裁决：有界递归混合架构。** 取两者之长：

1. **arc 顶层骨架定全局**——它已经在产出关键问题（core_truths）、每阶段伏笔收束计划、高潮、结局、体量估算。**停点由骨架钦定**，不依赖每步问"该停了吗"。
2. **逐阶段展开 + 章号重锚定**——递归是对的*机制*，但要被骨架约束；每展开一个 phase 就把章号从上一阶段实际结束处重排，**漂移不跨阶段累积**。
3. **完整性裁决兜底**——"初始大纲必须很好"的风险用 *消毒 + 重锚定 + 裁决* 从结构上化解，而不是赌一次生成完美。

## 二、数据流

```
选定 ArcRun（含 phases / core_truths / 体量估算）
        │
        ▼
_sanitize_phases ── 修复阶段范围：从 当前章+1 起、连续单调、修 end<start/重叠/缺口、
        │           每阶段 clamp 到 [4,24] 章
        ▼
对每个 phase：outline.refine(arc 源, phase_index,
        │       chapter_start/end override,            ← 用消毒后的干净范围
        │       continuity_hint = 上一阶段结尾,          ← 阶段间承接
        │       persist=False)                         ← 不污染 OutlineRun 列表
        ▼
聚合所有阶段章节 → 章号连续重排（re-anchor）            ← 杀掉 tail 漂移
        │           + _clean_title 剥离模型残留的"第N章"前缀
        │           + _str_list 兼容 dict 形状的 must_include
        ▼
完整性裁决（doubao-code · JSON-in-text）：
        │   core_truths 是否都揭晓？主要伏笔是否收束？节奏有无断层？
        │   → {revealed_truths, unresolved_truths, resolved/still_open_foreshadow_ids,
        │      coherence_issues, coverage_note, verdict: pass|needs_work}
        ▼
StoryProjection（append-only）：after/end 章、总章数、阶段计划、全书大纲、裁决
```

## 三、组件与文件

| 层 | 文件 | 职责 |
|---|---|---|
| 编排 | `backend/app/arc/project.py` | `_sanitize_phases` / `project_full_book` / `_judge_completeness` / `_clean_title` / `_str_list` / job 持久化 |

## 四、关键工程点

- **章号重锚定**是核心：模型常把原章号烤进标题（"第169章…"），且每个 phase 各自从其请求区间起编号；聚合后统一用 `chapter_index` 连续重排，并 `_clean_title` 剥离残留前缀，保证全书编号 0 缺口。
- **JSON-in-text**：`outline.refine` 与完整性裁决都吃大上下文（~9 万字），统一走 JSON-in-text（贴 schema + `json_repair`），不用 forced tool_choice（doubao 系在大上下文下会静默吞输出）。
- **非致命**：单个 phase 展开失败只丢该阶段、不拖垮整本推演；裁决失败也只标 `unknown`。
- **后台 job + stage**：整本推演耗时长（6 阶段 × 重型大纲调用，约 10-15 分钟），前端轮询 `stage`（"展开阶段 N/6…" → "完整性裁决" → done）。

## 五、验证结论（天之炽）

`arc#0《龙战于野·梵天陨落》`（6 阶段）→ 推演出 **第 157–227 章 / 共 71 章**全书逐章大纲：
- **章号 0 缺口、完全连续** —— 验证重锚定彻底解决了 raw arc 的 tail 倒挂；
- 抵达结局（225 梵天陨落倒计时 → 227 红莲绽放）；
- 完整性裁决 `needs_work`：6/6 关键问题揭晓、主线伏笔收束，但诚实标出 3 条游离伏笔 + 待修问题（节奏/逻辑），**在读 71 章之前就把缺口暴露**。

> 局限与下一步：`needs_work` 说明"一次推演"给的是**结构完整、覆盖到结局的骨架**，细节仍可补。后续可加：阶段边界去重、对 `needs_work` 缺口的修补推演、在全书大纲上一键逐章成稿（串起 draft 管线即整本成书）。
